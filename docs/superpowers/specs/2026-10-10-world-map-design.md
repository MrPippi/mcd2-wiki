# Minecraft Dungeons II 繁中 Wiki — 世界地圖設計規格

- 日期：2026-10-10
- 狀態：已核准（修訂 1：座標驗證後依實際資料調整標記種類，使用者已確認）
- 基準：`master`（`e0296bc`，PR #8 合併後）；分支 `feat/world-map`（worktree `.claude/worktrees/world-map`）
- 使用者選擇：全圖＋標記；Overworld、Sift、Camp 三個世界全做；Leaflet＋圖塊金字塔；「區域傳送點」改為裂隙＋城鎮傳送門；室內區域第一版不做

## 1. 目標

新增一個可縮放、可拖曳的世界地圖頁，底圖用遊戲自己的俯視全圖，上面標出礦車站、裂隙、城鎮傳送門、商人與區域名稱，可依種類篩選與依名稱搜尋。

### 1.1 成功標準

1. `/zh/map/`、`/en/map/` 顯示主世界全圖，可滑鼠滾輪／觸控縮放與拖曳；只載入畫面內的圖塊。
2. 世界分頁切換主世界／隙浮／營地（名稱取遊戲 `WorldMapLabels`），網址以 `?world=overworld|sift|camp` 記錄；無效值退回主世界。
3. 網址 hash `#z/px/py` 記錄縮放與中心點（最高層級像素），重新整理或分享後回到同一視角；超出範圍的值夾回範圍內。
4. 五種標記（礦車站、裂隙、城鎮傳送門、商人、區域名稱）各有勾選框（附該世界的數量），取消勾選即隱藏該類；選擇記在 `localStorage`，讀寫失敗或內容損壞不影響頁面。
5. 標記名稱搜尋：輸入後列出符合者（名稱或所在區域，不分大小寫，去頭尾空白），點選即飛到該標記並開啟其說明；無結果顯示「找不到」。
6. 點標記顯示名稱、所在區域與說明（裂隙、商人有遊戲說明文字）。
7. 中英切換保留 `?world=` 與 hash。
8. 標題列與首頁分類列各有「地圖」入口。
9. 無 JavaScript 或 Leaflet 載入失敗時，顯示該世界的縮小全圖與「需要 JavaScript 才能互動」提示。
10. 手機寬度（360px）無橫向捲軸，篩選面板移到地圖下方。
11. 網站部署在子路徑（`BASE_PATH=/mcd2-wiki/`）時圖塊與圖示路徑正確。
12. `npx tsc --noEmit` 無錯誤，單元測試與 E2E 全部通過。

### 1.2 非目標

- 室內區域（`DT_WorldIndoorAreaMapData`）：23 個中 17 個的室內場景擺在世界範圍外，門的位置是關卡內物件、不在 DataTables，沒有入口座標可用。
- 地下城內部（`Tile` 類傳送點）、Debug 傳送點、城鎮的玩家站位、塔內進出點、`FakeMinecartStation`。
- 物品掉落、怪物分布、任務標記；從條目頁連到地圖位置。
- 迷霧遮罩（`*WorldMap.png` 全白）。

## 3. 座標換算（已驗證）

### 3.1 公式

小地圖（`T_<World>_Minimap.png`，邊長＝`MapDims`）1px＝1 方塊，水平軸為遊戲 Y（向右遞增），垂直軸為遊戲 X（向上遞增），原點在左下角的 `MinPos`。BeautyRender 全圖是同一個方形縮小 `FancyMapSizeRatio` 倍、錨定在左下角：

```
u  = (y − MinPos.Y) / MapDims × ratio
v  = 1 − (x − MinPos.X) / MapDims × ratio
px = u × imageSize,  py = v × imageSize
```

### 3.2 驗證紀錄（2026-10-10）

在 Overworld 原始圖塊 `Overworld_04_00.png` 上標出下列點，皆落在對應建築上（誤差數 px）：

| 地標 | Location（cm） | 全圖像素（8192） |
|---|---|---|
| 鐵匠 | 16451.92, −10210.71 | 357.9, 4282.8 |
| 附魔匠 | 12377.40, −7221.26 | 510.9, 4491.4 |
| 商人 | 14800, −7460 | 498.7, 4367.4 |
| 傳送雕像 | 13845, −8750 | 432.6, 4416.3 |

Overworld 與 Sift 全圖上所有礦車站、裂隙皆落在陸地與道路上。Camp 沒有任何標記資料，只顯示底圖。

### 3.3 介面 `src/lib/map/transform.ts`（純函式）

```ts
interface WorldFrame { minX; maxX; minY; maxY; span; ratio; imageSize }  // 皆 number
toBlocks(location: { X: number; Y: number }): { x: number; y: number }
isInside(frame, block): boolean
toImagePixel(frame, block): { px: number; py: number }
```

## 4. 架構

### 4.1 圖塊 `scripts/map-tiles/`（新目錄，新指令 `npm run tiles`）

`npm run assets` 是素材索引報告，不產出網站檔案，所以圖塊用獨立指令。

- 最高層級 `zMax = ceil(log2(imageSize / 256))`：Overworld 5、Sift 5、Camp 4。該層每張 1024px 原圖直接切成 4×4 張 256px 圖塊，不先拼整張大圖。
- 往下每層：每張圖塊由上一層 2×2 張圖塊拼成 512px 後縮成 256px；缺的子圖塊以透明補齊。一路到 z0。
- 輸出 `public/map/<world>/<z>/<x>/<y>.webp`（`x` 行、`y` 列），webp 品質 80。
- `public/map/<world>/manifest.json` 記錄原圖的檔名、大小、mtime；完全相同時跳過該世界。
- 任一原圖缺檔：指令失敗並列出缺的檔名。
- 新增 devDependency `sharp`。

### 4.2 標記 `scripts/extract/map*.ts`（接在 `npm run extract`）

輸出 `src/data/map.json`（zod 驗證）：

```ts
type MapData = { worlds: WorldMap[] };              // 依 overworld、sift、camp 排序；缺資料的世界不列
type WorldMap = {
  key: "overworld" | "sift" | "camp";
  name: { zh: string; en: string };
  frame: WorldFrame;
  zMax: number;
  markers: Marker[];
};
type Marker = {
  id: string;                                        // 來源列名稱，世界內唯一
  kind: "minecart" | "rift" | "portal" | "merchant" | "area";
  px: number; py: number;                            // 全圖像素，四捨五入到 0.1
  name: { zh: string; en: string };
  area?: { zh: string; en: string };                 // 所在區域
  note?: { zh: string; en: string };                 // 遊戲說明文字
  icon?: string;                                     // public/ 下的路徑
};
```

- 每個點以 `Bounds` 判斷屬於哪個世界；不屬任何世界 → issue `map-marker-outside`，不輸出。
- 名稱查不到 → issue `map-missing-name`，不輸出；區域名稱查不到時只省略 `area`。
- 礦車站 `TeleportTag` 對不回 → issue `map-unmatched-tag`。
- 區域名稱標記：收集該世界所有礦車站、裂隙、傳送門的 `AreaTag`，每個 `AreaTag` 一個標記，位置取這些點的平均；名稱查不到則不標。
- 圖示：傳送門與區域名稱的圖示複製到 `public/icons/map/<檔名小寫>.png`（經現有 `copyIcons`）；檔案不存在 → 省略 `icon`，不報錯。礦車站、裂隙、商人沒有遊戲圖示，用 CSS 繪製。
- `DT_WorldRegionMapData.json` 不存在 → `map.json` 為 `{ worlds: [] }`，issue `missing-map-tables`。

## 5. 部署與大小

CI 沒有 `source-data`，`public/map/`、`public/icons/map/`、`src/data/map.json` 需 commit。預估圖塊 10–15MB；實作時量實際大小，超過 20MB 先降 webp 品質，仍超過再捨棄最高層級並回報。

## 6. 錯誤處理與邊界

- 抽取：超出範圍、名稱缺、tag 對不回 → 報告並隱藏；資料表不存在 → 空地圖＋報告。
- 圖塊：缺檔 → 指令失敗。
- 前端：Leaflet 初始化失敗 → 備援縮圖保持可見；`localStorage` 讀寫包 try/catch、內容損壞視為空；`?world=` 無效 → 第一個世界；hash 無效 → 預設視角，超出範圍 → 夾回；切換世界時重設視角；搜尋無結果 → 「找不到」。
